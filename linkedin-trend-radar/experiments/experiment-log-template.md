# Experiment Log Template

**Belongs to:** LinkedIn as input radar
**Artifact type:** Experiment template
**Release phase:** Phase 2 — Make it richer and usable
**Status:** Template
**Data posture:** Minimized / controlled working layer

## Purpose

This template defines a reusable experiment log for testing whether a LinkedIn-based radar workflow can produce useful observations, classified signals, evidence tasks, governance questions, adoption questions, vendor evaluation questions and content ideas without scraping, browser automation or unnecessary personal-data processing.

The experiment log is used before, during and after a radar experiment.

It should document:

```txt
what is being tested
which inputs are allowed
which inputs are excluded
how observations are minimized
how AI assistance is limited
which outputs are expected
how records are reviewed, retained, archived or deleted
```

## Experiment question

```txt
What is this experiment trying to learn?
```

Example:

```txt
Can a weekly manual LinkedIn radar review produce useful, minimized and reviewable signal notes around AI agents, governance pressure and adoption friction without storing copied posts or identifiable source records?
```

## Hypothesis

```txt
If the radar uses manual observation, source archetypes, minimized notes and structured classification, then it can produce useful trend-note candidates and handoff questions without needing scraping, feed mining or profile-level source databases.
```

## Input rules

### Allowed inputs

```txt

source archetypes
topic clusters
interest triggers
signal classifications
maturity levels
manually saved public links where necessary and proportionate

```

### Restricted inputs

Use only with clear need, controlled access and review.

```txt
specific source references
post URLs
employee-submitted observations involving third parties
profile-level notes
personal account analytics

```

### Prohibited inputs

```txt

reaction datasets

sensitive inferred attributes

```

## AI-assisted use

AI may support:

```txt
classifying source archetypes
suggesting interest triggers
suggesting signal types
assigning preliminary maturity levels
identifying evidence gaps
drafting fictionalized trend-note examples
suggesting governance, adoption, vendor or content questions
summarizing minimized weekly observations
```

AI should not be used to:

```txt
extract posts at scale
scrape LinkedIn
process raw connection exports without review
profile named individuals
rank people by trustworthiness
infer sensitive attributes
store unnecessary identifiers
turn comments or reactions into datasets
```

## Experiment workflow

```txt
1. Define experiment purpose.
2. Define radar topic clusters.
3. Define source archetypes of interest.
4. Define allowed and prohibited inputs.
5. Run weekly manual review.
6. Capture minimized observations.
7. Classify source archetype.
8. Classify interest trigger.
9. Classify signal type.
10. Assign maturity level.
11. Identify evidence needs.
12. Decide next action.
13. Review retention status.
14. Convert selected patterns into fictionalized examples.
15. Complete retrospective.
```

## Weekly review cadence

| Week   | Focus                           | Output                               |
| ------ | ------------------------------- | ------------------------------------ |
| Week 1 | Initial scan and signal capture | Watchlist entries                    |
| Week 2 | Repetition and source diversity | Evidence tasks                       |
| Week 3 | Pattern clustering              | Trend note candidates                |
| Week 4 | Handoff and fictionalization    | Example candidates and retrospective |

## Success criteria

The experiment is successful if it produces:

```txt
at least 8 minimized observations
at least 3 useful watchlist entries
at least 2 external evidence tasks
at least 1 governance question
at least 1 adoption question
at least 1 vendor evaluation question
at least 1 content idea
at least 3 fictionalized example candidates
no unnecessary personal data stored
clear retention decisions
clear improvement backlog
```

## Output categories

| Output                     | Description                                                        |
| -------------------------- | ------------------------------------------------------------------ |
| Watchlist entry            | Interesting but too early or unclear                               |
| Trend note candidate       | Signal has enough structure for deeper review                      |
| External evidence task     | Claim needs verification beyond LinkedIn                           |
| Governance question        | Signal raises risk, accountability, compliance or control issue    |
| Adoption question          | Signal raises workflow, role, capability or operating-model issue  |
| Vendor evaluation question | Signal raises claim-assessment or procurement issue                |
| Content idea               | Signal reveals communication, explanation or framing need          |
| Fictionalized example      | Shareable archetype-based case derived from minimized signal logic |
| Archive / delete decision  | Record no longer active, necessary or proportionate                |
