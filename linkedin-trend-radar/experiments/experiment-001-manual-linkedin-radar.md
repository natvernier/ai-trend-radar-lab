# Experiment 001 — Manual LinkedIn Radar

**Belongs to:** LinkedIn as input radar
**Artifact type:** Experiment
**Release phase:** Phase 2 — Make it richer and usable
**Status:** Ready to run
**Data posture:** Minimized working layer
**Experiment type:** Manual radar experiment

## Purpose

This experiment tests whether a manual-first LinkedIn radar can produce useful, minimized and reviewable signal notes from real LinkedIn observations without copying posts, scraping feeds, storing unnecessary personal data or creating a profile-based source database.

The experiment uses real LinkedIn posts only as inspiration for signal detection.

The final outputs should be:

```txt
minimized observations
classified signals
evidence tasks
governance questions
adoption questions
vendor evaluation questions
content ideas
fictionalized example candidates
```

The experiment should also test whether real posts can be transformed into fictionalized, realistic and archetype-based examples without exposing the original source.

## Core experiment question

Can a weekly manual LinkedIn radar review produce useful, privacy-aware trend radar outputs from real professional discourse while keeping the working records minimized, non-extractive and safe for fictionalization?

## Hypothesis

If LinkedIn posts are treated as discovery inputs rather than extracted content, then a manual radar workflow can produce useful organizational intelligence through:

```txt
source archetypes
minimal observations
signal classification
maturity assessment
evidence review
fictionalized case transformation
```

without needing scraping, copied post archives or person-level source tracking.

## Weekly workflow

Use this sequence during each weekly review.

```txt
1. Review active topic clusters.
2. Manually review LinkedIn feed or saved observations.
3. Capture only minimized observations.
4. Replace source identity with source archetype.
5. Classify interest trigger.
6. Classify signal type.
7. Assign maturity level.
8. Identify evidence status.
9. Identify organizational implication.
10. Decide next action.
11. Mark fictionalization potential.
12. Review retention status.
13. Delete or archive unnecessary records.
```

## Weekly output target

Each weekly session should produce approximately:

```txt
2–4 minimized observations
0–2 watchlist entries
0–2 evidence tasks
0–1 governance question
0–1 adoption question
0–1 vendor evaluation question
0–1 content idea

```

Do not force outputs.

A week with mostly discarded observations can still be useful if it improves feed quality.

## Retention rules

### Delete

Delete records when:

```txt
the observation is not relevant
the signal is too vague
the record contains unnecessary identifiers
the record has no clear next action
the record is not proportionate to retain
```

### Review

Review records when:

```txt
the signal is interesting but early
evidence is missing
source diversity is unclear
the signal may become useful later
traceability risk needs checking
```

### Keep

Keep records when:

```txt
the signal supports the radar purpose
the next action is clear
evidence work is needed
the observation may become a trend note
the observation may become a fictionalized example
```

### Archive

Archive records when:

```txt
the signal is no longer active
the record has historical value
the record should not remain in active review
```
